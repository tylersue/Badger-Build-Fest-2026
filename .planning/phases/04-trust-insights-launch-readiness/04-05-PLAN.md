Create features/trust/reviews.ts (pure plus one thin action via commitDemo, D-02):
- `export const REVIEW_UNLOCK_MESSAGES = 5` (MKT-05) and `export const REVIEW_COMMENT_MAX = 1000`.
- `export function messagesSentTo(s, agentId, identityId): number` counts role "user" messages across every conversation in allConversations(s) with that agentId whose hirerId is identityId. Sandbox threads are not conversations and never count.
- `export type ReviewEligibility = { status: "eligible"; sent: number } | { status: "locked"; sent: number; needed: number } | { status: "reviewed"; review: Review } | { status: "owner" } | { status: "unavailable" }`.
- `export function reviewEligibility(s, agentId, identityId)` checks in this order: agent missing or status not "published" gives unavailable; owner gives owner; an existing review by identityId gives reviewed; fewer than REVIEW_UNLOCK_MESSAGES sent gives locked; otherwise eligible.
- `export function validateReviewInput(input: { stars: number; comment: string })` returns `{ ok: true; stars: ReviewStars; comment: string | null }` or `{ ok: false; error: "invalid_stars" | "comment_too_long" }`. Stars must be an integer 1..5. The comment is trimmed; empty becomes null; the length check is on the trimmed text.
- `export function rollRating(avg: number, count: number, stars: ReviewStars)` returns `{ ratingAvg: Math.round(((avg * count + stars) / (count + 1)) * 100) / 100, ratingCount: count + 1 }`.
- `export function planReview(s, agentId, identityId, input, now: string, id?: string)` returns `{ ok: true; review: Review; rating }` or `{ ok: false; error: ReviewEligibility["status"] | "invalid_stars" | "comment_too_long" }` (never "eligible"). The rating comes from rollRating over the agent's current ratingAvg and ratingCount as returned by agentById.
- `export function applyReview(s, plan)` appends to `reviews` and merges `{ ratingAvg, ratingCount }` into `agentEdits[agentId]` without touching updatedAt.
- `export function submitReview(agentId, input)` is the action. The identity is currentIdentity(readDemo()). It re-plans inside the commitDemo updater so a double click cannot create two reviews, and returns the inner result.
