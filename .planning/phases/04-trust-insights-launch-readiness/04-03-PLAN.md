Create features/billing/cashout.ts (pure plus one thin action via commitDemo, D-02):
- `export const CASHOUT_USD_CENTS_PER_CREDIT = 1` (CRED-09: 1¢ per credit).
- `export type CashoutSummary = { balanceCents: number; lifetimeEarningsCents: number; lifetimeCashoutCents: number; availableCents: number; payouts: Payout[] }`.
- `export function cashoutSummary(s, identityId)`:
  - lifetime earnings is the sum of that identity's `earnings` rows
  - lifetime cash-outs is the negated sum of its `cashout` rows
  - availableCents = max(0, min(balance, lifetimeEarnings − lifetimeCashouts))
  - payouts come from payoutsFor
  - Capping cash-out to earned credits is Claude's discretion (flagged below). It keeps seed, plan and pack credits from being paid out.
- `export function planCashout(s, identityId, credits: number, now: string, ids?: { ledgerId: string; payoutId: string })` returns `{ ok: true; ledgerRow: LedgerEntry; payout: Payout }` or `{ ok: false; error: "invalid_amount" | "nothing_available" | "exceeds_available" }`.
  - credits must satisfy Number.isSafeInteger and be > 0, otherwise invalid_amount
  - available 0 gives nothing_available; above available gives exceeds_available
  - ledgerRow: kind "cashout", amountCents −credits, balanceAfter balance − credits, purpose null, refType "payout", refId payout.id, note "Mock cash-out · {formatUsd(credits × rate)} requested · no payment sent", createdAt now
  - payout: status "requested", amountUsdCents credits × CASHOUT_USD_CENTS_PER_CREDIT, ledgerEntryId the row id
  - Default ids come from crypto.randomUUID() inside the function, prefixed "l-" and "p-".
- `export function applyCashout(s, plan)` appends the row to `ledger` and the payout to `payouts` in one state.
- `export function requestCashout(credits: number)` is the action. The identity is currentIdentity(readDemo()). It re-plans inside the commitDemo updater against the state the updater receives (double-submit guard), keeps state unchanged on failure, and returns that inner result.
