## Findings and work in progress

- The published Maria fixture appears in the marketplace while its Publish checklist reports **0/5 active knowledge chunks**. Fixture conversation citations are useful for UI checks but are not evidence of current live retrieval.
- `Acceptance 57259071` has a saved answer that Knowledge labels **Captured · not searchable yet**; the interview labels it **Updating knowledge**. The indexed acceptance agent `Acceptance 8262cb34` is the better live-source test target.
- Mobile builder tabs extended the document to 455 px. `app/(app)/build/[agentId]/layout.tsx` now gives the tabs a bounded horizontal scroller. Post-build check: `nav.scrollWidth=471`, `nav.clientWidth=390`, and document width=390.
- Marketplace cards extended the mobile document to 416 px. `components/app/marketplace.tsx` now allows grid items and cards to shrink. Post-build document width=390.
- The mobile sidebar was inaccessible because its only trigger lived inside the hidden sidebar. `components/app/ui.tsx` now puts a trigger in the breadcrumb bar. Post-build, the mobile drawer and identity switch both opened.
- Source preflight on the draft agent showed **14.144 credits already held**. No existing hold was released or reset. No upload was confirmed and no paid browser message was sent while the runtime migration and metered experiment were running.
- After the metered run cleared the gate, a 269-byte synthetic paste on `Acceptance 8262cb34` preflighted at **0.00027 credits** estimated with an 8-credit maximum hold. Initial confirmation returned a sanitized `invalid_input` / “Invalid request.” A read-only database check found a failed source/intake job with `parse` error; that operation settled with `held_units=0`. The original failed source remains visible at 0 chunks, 0 credits charged, and 0 pending settlement.
- The production Webpack chunk had compiled static `createRequire(...).resolve` to `(void 0).resolve`, breaking the parser even for plain pasted text. The runtime fix uses `process.getBuiltinModule('module').createRequire` only for PDF/DOCX; plain text no longer resolves either package. After the rebuilt site restarted, a **fresh** estimate and one confirmation of the same text produced `Synthetic QA source 2026-09-27` as **TEXT · Ready**, **1 chunk**, charged **0.000106 credits**, pending settlement **0 credits**. Reload preserved that source alongside the old failed record and five original Ready sources.
- Test > Configure > Knowledge listed the old failed synthetic source as **Processing…**, while the Knowledge page correctly listed it as **Failed**. The UI mapping in `components/app/builder.tsx` rendered every non-Ready status as Processing; it now distinguishes Queued, Processing, and Failed. Targeted ESLint and TypeScript checks passed, and the final production build showed the old source as **Failed** beside the new **Ready · 1 chunks** source.
- The pasted text was one plain-ASCII paragraph, with no Markdown heading or Unicode: “Synthetic site QA source. This text contains no personal data. When reviewing a resume bullet, ask what the applicant did, what changed, and what evidence supports the result. Never invent experience or attach an expert citation to a claim that the expert did not make.”
- Chrome's supported file chooser did not open for a `.txt` upload, so browser file selection could not be verified. Its troubleshooting instruction is to enable **Allow access to file URLs** in the ChatGPT browser extension’s Details under `chrome://extensions` ([instructions](https://developers.openai.com/codex/app/chrome-extension#upload-files)).
- Automatic approval review rejected checking the content-ownership/license box on the synthetic agent as a consequential legal acknowledgment not explicitly authorized by the user. The checkbox remains unchecked and the agent remains draft; no indirect publication path was attempted.
